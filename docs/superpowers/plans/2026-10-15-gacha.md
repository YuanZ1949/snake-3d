# 抽卡（祈愿）系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为贪吃蛇游戏加入原神式祈愿抽卡：吃果星尘双轨货币、原神概率保底、CSS 流星动画、11 款程序化新皮肤（含 5星流光特效）。

**Architecture:** 服务端 serve.py 负责全部权威状态（星尘余额、库存、保底计数、概率判定），新增纯函数 `gacha_roll`（rng 可注入）+ 两条消息 `gacha`/`gachainfo`；客户端 index.html 扩充 SKINS 数组、新增祈愿全屏覆盖层（CSS 流星 → 爆闪 → 卡片翻出）与 canvas 立绘卡。单文件架构不重构。

**Tech Stack:** Python 3 + asyncio WebSocket（既有）；原生 JS/CSS/Canvas（既有）；无新依赖。

**Spec:** `docs/superpowers/specs/2026-10-15-gacha-design.md`（本计划的每个数值以 spec 为准）

## Global Constraints
- 概率/余额/保底/库存全部服务端判定，客户端消息不可信；客户端只播动画。
- Store users JSON 新字段一律防御式读取（`u.get(key, default)`），旧账号无缝兼容。
- 现有 5 款免费皮肤（SKINS 下标 0-4）永不需拥有、不受鉴权限制。
- 新皮肤 id 分配：5-10 = 3★×6（赤霞/青岚/墨影/鎏银/樱粉/沙金）、11-13 = 4★×3（星河/雷纹/霜纹）、14 = 5★常驻白金圣蛇、15 = 5★UP 辉夜。
- 数值（verbatim from spec）：5★1.6%、硬保底 90、50/50 大保底；4★13%、10 抽必出；定价 160/抽、1600/十连；重复返还 3★10/4★50/5★200；吃果当场星尘 +1，局末/死亡/离房 1:1 入总账。
- 未登录：可显示当场星尘但不可抽（gacha 回 error 引导登录）；死亡/离房时未登录的当场星尘直接丢弃。
- 门禁：`.venv\Scripts\python.exe test_game.py` 全绿（当前 110 起）、`node C:\Users\yuan\AppData\Local\Temp\opencode\static_check.js index.html` 全绿（当前 js=581 起）、`pwsh scripts\local_ci.ps1` ALL GREEN。
- 探针/取证脚本放 `test-results/`，跑 local_ci 前备份到 `C:\Users\yuan\AppData\Local\Temp\opencode\`。
- 提交：`git add` 后直接 `git commit`（默认 autocrlf 归一），真账看 `git show --numstat`。

## Review Focus
- **余额竞态/双花**：同一 Session 并发两条 gacha 消息 → 服务端处理是单协程顺序的，但测试要钉住「余额不足时库存与保底计数不变」（Task 3 的 `test_gacha_insufficient_balance_no_side_effect`）。
- **保底与 50/50 状态跨十连**：十连 10 抽串行判定，保底计数逐抽累计 → Task 2 的 `test_gacha_ten_pull_pity_carry` 用固定 rng 序列钉住。
- **当场星尘双计**：死亡已并账后又在局末并账 → settle 函数必须幂等（清零后不再入账），Task 3 的 `test_settle_dust_idempotent` 钉住。
- **皮肤鉴权绕过**：客户端伪造 `skin:15` 选未拥有的 UP 皮 → 服务端选皮/入局两处都要按库存鉴权（free 5 + 已拥有），Task 3 的 `test_skin_select_requires_ownership` 钉住。
- **动画卡死**：网络错误或跳过点击导致覆盖层永久锁输入 → Task 6 探针含「error 路径覆盖层可关闭」与「跳过后输入恢复」断言。

### Task 2: `gacha_roll` 纯函数 —— 概率、保底、50/50

**Files:**
- Modify: `serve.py`（新函数，放 Store 类之后）
- Test: `test_game.py`

**Interfaces:**
- Produces: `gacha_roll(rng, lose5050, pity5, pity4) -> dict`，`rng` 为 `random.Random` 实例（测试注入 seed）；返回 `{'star': 3|4|5, 'up': bool, 'pity5': int, 'pity4': int, 'lose5050': bool}`（后三项为更新后保底状态）。`up` 仅 star==5 时有意义（True=UP 辉夜 id15，False=常驻白金 id14）。皮肤 id 由调用方按 star+up 映射（GACHA_POOL 常量：`{3: [5..10], 4: [11,12,13], 5up: 15, 5std: 14}`，同星内 rng 均匀选取）。
- 规则（verbatim）：pity5==89 → 必 5★；pity4==9 → 必 4★；否则 rng.random()<0.016 → 5★，<0.146（0.016+0.13）→ 4★，否则 3★。出 5★：`lose5050=False` 时 rng 再掷 `<0.5` 给 UP；歪则 `lose5050=True`，`lose5050=True` 时必 UP 并重置。保底触发/出货后对应计数清零，未出的计数 +1。

- [ ] **Step 1: 写失败测试**：
  - `test_gacha_pity90_hard`：pity5=89 → star==5，pity5 归零。
  - `test_gacha_pity10_four`：pity4=9、pity5=0 → star in (4,5)，pity4 归零。
  - `test_gacha_5050_guarantee`：seed 序列驱动 loss → `lose5050==True`；下一次 5★ `up==True` 且 `lose5050==False`。
  - `test_gacha_ten_pull_pity_carry`：同一 rng 连 roll 10 次，断言 pity 计数单调累计逻辑正确（每次返回的 pity5 = 前值+1 或归零）。
  - `test_gacha_dist_smoke`：`random.Random(42)` 连抽 10000 次，5★ 落在 [80, 260]（1.6%±容差）、4★ 落在 [1000, 1700]——只验数量级，防概率写反。
- [ ] **Step 2: 跑测试确认失败** → FAIL（函数不存在）
- [ ] **Step 3: 实现** `def gacha_roll(rng, lose5050, pity5, pity4)`（按 Interfaces 规则，纯函数不碰 Store/全局）
- [ ] **Step 4: 跑测试确认通过**
- [ ] **Step 5: Commit** `feat(gacha): gacha_roll 概率与保底纯函数（批25 T2）`
