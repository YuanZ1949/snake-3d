# 自机预测 + 回滚（转向跟手）设计 Spec

> 批28 · 项 C。2026-10-16 · 状态：设计已获批（会话逐节确认），待 writing-plans 出实施计划。

## 1. 目标与意图

用户原话：「总感觉转向会落后操作一拍」。

根因（已查证，非 bug 而是架构性延迟）：

- 客户端**无本地预测**：`setDir`（index.html:2124-2139）只 `send({t:'dir'})` + 入 `dirQ`（`dirQ` 仅供跟随视角计算，:883），自机视觉蛇身完全等服务器回传 cells 才转向。
- 服务端**无多余一拍**（排除 bug）：收到 `dir` 立即入队 `p['queue']`（serve.py:2637-2638）；`game_cycle` 对到期蛇**先应用方向队列再用新方向算目标格**（:1314-1318 → :1328-1329），同移动周期生效。
- **延迟三段构成**：网络 RTT/2 + 等下一移动周期（`p['tick']`，基础 150ms/格，量化在 50ms cycle 上，0~50ms 额外排队）+ 渲染插值（`moveDt` 下限 60ms，index.html:2232/2907）。合计在远程服务器上 ≈ 2~3 拍。

目标：按键转向在自机**本地立即生效**并按服务器移动节奏本地推进，不等 RTT/下一帧快照；服务器快照始终是真相，不一致即回滚。开放地（直线/普通转向）应无感跟手；边缘复杂情况允许一次可见回弹。

## 2. 已拍板决策（用户逐项确认）

1. 方向：**客户端自机预测 + 回滚（真·跟手）**——否决「接受现状」「自机插值降滞后（治标）」「降 tick 50→33ms（改玩法数值）」。
2. 精度：**常见移动预测，边缘允许回弹**——否决「完整复刻服务器移动规则」与「仅即时转向反馈（最保守）」。
3. 对账：**方案 A：tick 锚定 + 输入缓冲回放对账**——否决方案 B（每帧硬对账：预测超前会被服务器快照逐帧回拉，产生微抖，抵消顺滑目标）。

## 4. 客户端设计（index.html，仅客户端）

### 4.1 组件：`predictor` 纯函数集（新增，不碰 DOM、可独立推理）

```js
predNextMoveAt(pred)                 // pred.lastMoveAt + pred.interval（interval 取服务器下发 myEnt.tick）
predAdvance(pred, inputs, statics, foods)
    // 到期推进一格：出队非反向输入换向；目标=墙/岩/传送门入口/出界(无幽灵) → 不推进只等待（防穿模回弹）
    // 落在 foods/bonus 已知格 → 保留尾巴（长一节）；否则去尾
predReconcile(pred, serverMy, inputs, statics, foods)
    // 以服务器 cells/dir 为基 → 重放 inputs → 「应处状态」
    // == 当前 pred → 无感，仅重锚相位；!= → 回滚到重放结果
```

- `inputs` = 既有 `dirQ`（不建第二份队列，复用其裁剪逻辑），`statics` = 持有的墙/岩/门，`foods` = 持有的果与 bonus。
- `pred = {cells, dir, lastMoveAt, interval, active}`，只对自机存在。

### 4.2 三个钩子点（既有位置各插一处）

1. **`setDir`（:2124）**：现状入队/发包不变 → 追加**旋转预览**：蛇头朝向取 `dirQ` 尾（仅改 `rotT[0]` 视觉，按键即刻响应）；**格子推进不在此处**，仍在 `predAdvance` 按 `dirQ` **队首逐次消费**（严格镜像服务器「一次移动消费一条转向」语义，防快速连按多输入被一次动消化 → 必然回滚）。
2. **渲染循环（rAF）**：`joined && myEnt.alive && !spectating && wsOpen` 且 `now ≥ predNextMoveAt` → `predAdvance`，并写插值锚点 `lastCells/cells/moveAt=now/moveDt=interval`——**滑动从本地时刻起步**，不再等快照到达。
3. **snap 处理（:2563 `applyPlayers` 之后、:2565 dirQ 裁剪之后）**：`predReconcile`。先接受服务器真相，再决定无感重锚或回滚。

### 4.3 相位锚定

- 首次收到自机有效 snap 建基准；此后用「自机 cells 变化的 snap 到达时刻」校正（服务器移动量化在 50ms cycle，到达误差 ±50ms，由 150ms/格的插值滑动吸收）。
- `interval` 每帧取服务器最新 `myEnt.tick`（speed/吃果变更立即跟随）。
- **超前上限一格**：本地绝不预测超过「上次移动 + interval」的下一格。

## 5. 对账与回滚规则

- **唯一输入源**：重放只用 `dirQ`（其裁剪已含 `q` 对账，:2565-2572），杜绝双队列失步。
- **不预测进已知实体**：墙/岩/传送门入口/无幽灵出界 → 悬停等服务器裁决，避免穿模后大幅回弹。
- **回滚表现**：`pred.cells = 服务器 cells`，沿用 `applyPlayers` 已设的插值锚点滑到位（不瞬移硬切）；本地预测推进时 `moveDt = interval`，与现状「每次移动滑一格」的节奏一致。
- **回滚触发即边缘场景**（撞墙反弹、传送门出口朝向、对头强制右转、眩晕/道具干扰、他蛇抢先吃果的滞后清单）——设计上**允许一次可见回弹**（已拍板）。
- **禁止事项**：不改变服务器任何判定；不弱化现有 `dirQ` 裁剪/清队；不为回滚引入额外协议字段。

## 6. 关闭/异常路径（预测同步停用或重置）

| 时机 | 动作 |
| --- | --- |
| 死亡 / `win_pending` / 新回合 / 复活 / 换房 / 重连 | 既有处理器已清 `dirQ`（:1890/:1943/:1986/:2611/:2703/:2747/:2794/:2826），同点 `pred = null` |
| 观战 / 大厅 / 演示蛇 / 未 join | 不启用（`joined && myEnt && alive && !spectating` 才 active） |
| `wsOpen=false` | 不预测（与批13④ :2127 同口径：没发出去就不许本地超前） |
| 服务器报死亡但客户端未收 die 事件 | snap 兜底路径（:2587-2590）随 `alive=false` 停用预测 |

## 8. 不做（本期边界）

- 不动服务端：零协议改动、不 bump `PROTO_VER`、不改 tick/数值/`game_cycle` 判定。
- 不预测他蛇、观战者、大厅演示蛇（保持现有插值）。
- 不复刻服务器边缘移动规则（撞墙反弹/传送门/对头右转/眩晕）——允许回弹即为此设计。
- 不移除/不削弱既有插值平滑与 `dirQ` 对账。
- 池内其他项（E/F/D/G/H/I）不越界。

## 9. 风险与假设

- **假设**：「一拍」主因 = 等下一移动周期（最多 150ms）+ RTT + 插值；本地预测移动时机可消掉 RTT/快照等待项。若部署后仍觉迟钝 → 二期再查相位精度（±50ms 量化误差）。
- **假设**：`p['tick']` 随 snap 实时可信（speed/吃果都改它），预测直接采用；若出现间隔突变导致预测抖动 → 以 reconcile 结果为准强制重锚。
- **风险**：相位估计误差 + 网络抖动可能造成轻微滑动步调不稳（±50ms 级，150ms/格下大概率无感）；确有可见抖动时的退路是「预测只换向、不本地推进格子」（降级为半预测，仍优于现状）。
- **风险**：Playwright 探针依赖喂 snap 的时序，flaky 时优先断言状态而非帧时刻。
