## 1. 背景与目标

给 3D 贪吃蛇对局引入**真高度层**：地图格子带高度，蛇逐节攀爬起伏，高地带来碾压权、架弹优势与弹道掩体，建筑是"形状规整的地形"。与水池、山峰同属一套地形系统。

**目标（验收方向）**：进房能看到拔高的山体/水洼/建筑/草；蛇翻山时身体逐节起伏；高撞低碾压、低撞高被挡；子弹被山体楼体挡、跨 2 层打不中；房间编辑面多三个地形旋钮；本地门禁全绿。

**非目标（本批明确不做）**：
- 编辑器逐格摆地图（字段设计留位，不实现）
- 据点占领系统（已拍板：纯天然据点）
- 视野迷雾（已拍板：只挡弹 + 立体视觉）
- 元素反应（独立子项目 B，后续单独立项）
- 爬坡条件化（加速才能上陡坡——后续批次可叠加）
- 高档美术（山体斜坡贴图、水面波光 shader；本批只做几何拔高）

## 3. 服务端模型

### 3.1 高度表

- `Room.hmap: dict[(x, y) -> int]`，稀疏表，**只存非平地格**（0=平地不存，键不存在即 0）。
- 与 `rocks/walls/portals` 并列，`build_terrain()` 每局重建（`new_round` 走 `build_terrain` 后 spawn、后 `place_food`，顺序天然正确：生成 → 出生 → 撒果）。
- **深渊不需要独立集合**：用 `h = 9` 编码（见 §4 编码表）——移动规则 `h - 头高 ≥ 2` 对 9 恒成立（最高合法高度 3，9-3=6 ≥ 2），蛇自动不可进，`_solid/occupied/reach_set` 全部复用同一张表、零特判。仅两处认 9：子弹"飞越"、渲染"画坑"。

### 3.2 编码表（单整数轴，负值=低地类型）

| h | 含义 | 蛇可进？ | 弹？ |
|---|------|---------|------|
| 9 | 深渊（黑坑） | 恒不可进（上行差恒 ≥2） | 恒飞越（特判 `h≠9` 才挡） |
| 3 | 高楼顶 | 上行差 ≤1 才可进 | `h > 弹h` 挡 |
| 2 | 山峰 | 同上 | 同上 |
| 1 | 山腰 / 屋面 | 可进（0→1） | `1 > 弹h0` 挡 |
| 0 | 平地 | —（不存） | — |
| -1 | 水洼 | 可进 + **减速** | 飞越（-1 > 弹h 不成立） |
| -2 | 草地（伏击草） | 可进 | 飞越 |

**通行规则（精确化，问题 4 的澄清）**：`目标h - 当前h ≥ 2 → 不可进（硬碰撞死，reason=cliff）`，**下行自由**（跳下山可以，爬峭壁不行）。若按 |差|≤1，草 -2 会被自己的规则挡死，且"上得去下不来"手感怪——故只限上行。水/草均在 0 以下，下行自由天然放行。

### 3.3 接入点（四个，全部已存在）

1. **`_solid(x, y, skip_pid, cur_h=None)`**：`cur_h is None` → 旧语义（食物/占位等场景不涉高度）；传值时 `hmap[(x,y)] - cur_h ≥ 2` 视为实心（含 9）。`_open_ahead`（AI 前瞻）跟随传蛇头当前格高，否则 AI 反复撞峭壁。
2. **`reach_set`（防孤岛 BFS）**：block 集追加 `h >= 2`（含 9）。水可进、山可绕，0/1/-1/-2 层天然互通，平面可达性简化仍正确（h=2 内芯可能成"无人可达空间"，无所谓，无人能进）。
3. **移动主路径 `step()`**：blockset 判定处追加高度差判定（`目标h - 头h ≥ 2` → 并入现有撞岩/墙的判死分支，died reason `cliff`）。
4. **`occupied(x, y)`**：`h >= 2`（含 9）视为占用（食物/道具/奖励不放不可达格）；`h <= 1` 与草水可被占用判定放行。

### 3.4 逐节高度取值（按格查表，无平行数组）

- 逐节高度**不落任何存储**：第 j 节高度恒 = `hmap.get(cells[j], 0)`。`hmap` 单源，服务端规则（碾压/挡弹/减速）与客户端渲染同源取值，不存在第二数组失同步的可能。
- 初稿曾设计 `p['cellh']` 平行数组，**计划期废除**（§12 修订①）：cells 每次 push/pop/截断/传送都要同步第二数组，漏一处即静默错高；查表零维护且 hmap 每局静态（局中不变），结果完全等价。
- 合法性前提：蛇只可能在有效格上（出生 h==0、移动受 §3.3 规则约束），查表对任意时刻的 cells 均成立；深渊（9）上不可能有蛇。

### 3.5 水洼减速

服务端 tick 侧：蛇头所在格 `h == -1` 时 tick 生效值 ×1.3（走 eff 或 tick 计算处，与现有减速类效果同机制）。不进协议（客户端有 hmap 可本地做水花反馈）。

## 4. 协议（PROTO_VER 27 → 28）

- `serve.py:48` 与 `index.html:1060` 的 `PROTO_VER` 同步 bump 28；`room-ok` 版本不等自动 `location.reload`（`index.html:2866`），双端同时换版。
- **`hmap` 加入 `Room.DELTA_FIELDS`**（C1 增量签名模式）：
  - 全量帧必带：`"hmap": [[x, y, h], ...]`（稀疏三元组列表）。
  - 增量帧：`snapshot()` 加序列化分支（dict 元组键 JSON 化不了，需 `[[x,y,h] for (x,y),h in hmap.items()]`），签名变了才带，客户端缺失沿用旧值——与 rocks/walls 完全同构。
- **弹道高度字段**：`snapshot()` 的 `proj` 序列化每条增 `"h": pr.get('h', 0)`（发射时记录的发射者头格高）——他弹渲染需要，客户端按其抬升弹体；缺失（旧帧）沿用 0。
- **不需要协议的**：碾压判定（服务端算）、水减速（服务端 tick）、逐节蛇高（客户端按 hmap 查格，§3.4）、伏击草/水花（客户端拿本地 hmap 与对方 cells 推）。
- 死亡事件沿用现有 ev 流，kill reason 新增值：`cliff`（撞崖）、`crush`（被碾压）。
- 房间配置：创建/编辑消息增三字段（§7.2），`info()` 回传 eff 值 + Custom 原样回填值。

## 5. 客户端渲染与手感

### 5.1 地形几何

- 生命周期与 `rockMeshes/portalMeshes` 同构：收到 `hmap` 字段即重建 `heightMeshes[]`（共享 `BoxGeometry`，按格拔高，`H_UNIT ≈ 0.35`/级）。
- 山/丘：岩色柱体、顶面提亮；水（-1）：下沉蓝色半透明面（y 低于地面 0.05，透明度缓慢呼吸）；深渊（9）：向下挖的黑色坑柱 + 顶面开口 + 边缘警示描边；草（-2）：贴地染色块画在 y=0；楼（1~3）：规整亮色柱体、顶面描边（建筑感靠形状规整+顶面高光，不靠贴图）。

### 5.2 深度处理（蛇恒可见的关键）

- **全部高度地形 mesh：`depthWrite = false`**（且草/水本来可透明）。
- 效果：山不写深度 → 蛇（正常深度测试）在山后依然画出 = 永远可见，杜绝"楼后藏人"的变相迷雾（问题 8 拍板无迷雾的必要保障）；岩石/墙/地面/蛇的现有遮挡关系零改动；格子柱体互不重叠，关 depthWrite 无互穿瑕疵。

### 5.3 蛇与子弹

- 每节按渲染高度 `visH(hmap.get(cells[j],0))` 得目标竖直高度，沿现有平滑插值机制逐节 lerp（插值分支对 from/c 两格高度也按 ph 混合；爬山时身体抬起、翻过山脊起伏——逐节高度的意义）；头节按相邻节高差做俯仰倾斜。
- **渲染高度映射 `visH`**（仅渲染层，规则仍用原始 h；§12 修订③）：`0~3 → h × H_UNIT`；**水 -1 → -0.12**（浅涉没半个身位）；**草 -2 → 0**（贴地不下沉——若直接乘 H_UNIT，草格上的蛇会被压到地面之下）。深渊 9 蛇不可达、无映射。
- 子弹飞行高度 = 发射者头高，尾迹同高；撞地形在碰撞点碎裂特效。
- 子弹/蛇渲染不动现有深度逻辑（仅受益于 §5.2）。

### 5.4 特效

- **伏击草**：对方蛇（非本机 pid）**任一节所在格 `h == -2`** → 整条渐变至 opacity ≈ 0.35（蛇身是单材质 tube 网格，逐节透明需顶点色改造——§12 修订⑤降级为整蛇级淡出，带平滑过渡防闪）；**自己蛇不淡**（全亮）。纯客户端，零协议。
- **水花**：自己头节在 `h == -1` 格 → 头部水花粒子/涟漪环。
- HUD 无新元素（kill feed 沿用 ev，reason 视觉可简化为文字）。

## 6. 碰撞与弹道细节

### 6.1 撞崖 = 硬碰撞

`目标h - 头h ≥ 2` 并入**现有 blockset 判死路径**（撞岩石/墙同路）——自动继承全部既有豁免（shield 不死、walldeflect 只折边界、deflect/shield 期不悬停等），零新分支。died reason `cliff`。AI 靠带 `cur_h` 的 `_open_ahead` 提前避让，玩家靠立体视觉预判。

### 6.2 碰撞语义（step 现有碰撞段内插高度比较；§12 修订②）

现有代码语义（写计划时核实）：头入他蛇身体 = **咬击**（截断对方、score/kill 归攻击者，核心 PvP 攻击，`step()` section 5）；头撞头 = 强制右转 + STUCK_TICKS 破僵局（不即时死）。初稿的「新头格 h vs 被撞节 h」还有同格恒等悖论（头进入的格即被撞节所在格，比较恒相等）。**统一比较基准 = 撞击前各自蛇头所在格高（stance，站得高者赢）**：

- **头撞对方身体节**：`我当前头格 h vs 被撞节所在格 h`：
  - 我更高 → **对方整条死**（reason `crush`；结算沿 min-len 咬死路径：grow/score/ult/kills 归我，ev `bite`(kill) + `die`(crush)）。
  - 同高 → **现有咬击截断逻辑原样不变**（同层互咬是既有核心玩法，不判死）。
  - 我更低 → **我死**（reason `crush`，低咬高反噬；shield 不豁免——PVP 接触非地形；对方 `_protected` 照旧 skip_move 不判）。
- **头撞头**：比**撞击前**双方头格高——异高：低者死（reason `crush`）、高者不右转照常移动；同高：现有强制右转 + STUCK_TICKS 破僵局原样不变。head-on 判死沿用 section 3 现状不查保护。
- **同帧多头撞同节**：沿用现有 bites 聚合框架（每受害者取最小 idx 的攻击者），对选中的 `(eater, idx)` 对做一次高度裁决。
- **自撞不比高**：维持现状直接死（否则从山顶跳下穿过自己身体会免死，反直觉）。
- 与撞崖的先后：cliff 判定在 section 4（先于咬击 section 5），同帧双条件时 cause 取 `wall > rock > cliff`。

### 6.3 架弹与弹道（`_step_projectiles` 逐帧、逐格）

- 发弹记 `弹h = 头格高`。
- **地形挡弹**：弹所在格 `h > 弹h` 且 `h ≠ 9` → 弹碎（深渊恒飞越）。
- **跨层命中**：`|目标节h - 弹h| ≤ 1` 才命中，差 ≥2 掠过（0 层打不到 2 层山顶——山顶是安全掩体，破局靠上山腰对射或堵下山口）。
- rage 弹幕 / ult 走同一条 `_step_projectiles`，同规则。

### 6.4 道具豁免

- ghost 期间：高度地形与深渊**全穿透**（沿用穿墙语义）。
- 其余道具不新增分支（高度碰撞走岩/墙同路，豁免自然继承）。

### 6.5 平衡观察点（实测后调，不阻塞交付）

- 山顶 2 对山腰 1 是**单向弹优势**（山腰弹被山体挡、山顶反打能中）——高位=强是既定共识，靠山格稀缺 + 爬坡路线成本平衡。观察指标：山顶驻留时长、山顶击杀比；调参手段：命中范围、山体生成密度。
- 碾压 + 伏击草组合（草里埋伏低打高/跳杀）是否过强，同样留给实测。

## 7. 配置与生成

### 7.1 主题表（`THEME_CFG` 每主题增三键）

建议初值（实测可调）：

```python
'default': {..., 'hill': 0.9, 'water': 0.6, 'bld': 0.5}
'lava':    {..., 'hill': 1.4, 'water': 0.0, 'bld': 0.3}   # 无水洼（熔岩用现有主题色表达）
'ice':     {..., 'hill': 0.5, 'water': 0.9, 'bld': 0.4}
'space':   {..., 'hill': 1.1, 'water': 0.0, 'bld': 0.9}   # 浮岛楼宇
'day':     {..., 'hill': 0.8, 'water': 0.7, 'bld': 0.6}
```

### 7.2 房间旋钮（沿用 rock_mult 模式，三个）

- `Room.__init__` 增参 `height_mult=None, water_amt=None, bld_amt=None`（None=跟随主题，0=关闭）。
- 创建/编辑消息：消息字段定名 `height` / `water` / `bld`，即 `d.get('height')` / `d.get('water')` / `d.get('bld')`（数字=倍率/量级、0=关闭、缺省/None=跟随主题）。
- `info()` 增：eff 值 + `heightCustom / waterCustom / bldCustom`（原样回传，None=跟随主题）——与 `rockCustom/portalCustom` 同模式。
- 编辑面：`cRock` 旁加三个输入框（回填逻辑同 `index.html:3907` 的 `cRock` 模式：空=跟随主题）。**本批不做逐格摆放**，只做旋钮。

### 7.3 `gen_heights()`（`build_terrain()` 末尾追加）

- **预算**：全房非平地格 `h ≠ 0` 总数 ≤ **35%** 格子数（三类共享预算池，超限即停）。
- **顺序**：山包 → 水洼 → 建筑（互不重叠；全部避开：portal、wall、旧蛇头 ±4 格、已放地形）。
- **山包**：种子数 `≈ 面积/40 × hill`（主题×旋钮）。种子 h=2，`70%` 阶梯山（邻格放 h=1 环）/ `30%` 一侧不放环（该面成 0→2 立地峭壁，刻意保留"进不去但看得见"）。
- **水洼**：`≈ 面积/60 × water`，随机游走 blob 3~8 格全 h=-1，避山/墙/门/头。
- **建筑**（规整=与水池山峰同级的地形）：`≈ 面积/80 × bld`，矩形 footprint（1×2 / 2×2 / 1×3 / 2×3）：
  - h=1（40%）：可直接走进的矮房，屋顶即高台（0→1 可进）。
  - h=2（35%）：其中 `60%` 带一格 h=1 入口坡（可攻占高台）、`40%` 纯立地塔。
  - h=3（25%）：纯掩体塔，不可上。
- **出生点强制 `h == 0`**：`_spawn_player_impl` 主路径与兜底①选点加该条件（出生在水/草/山上均不允许）；兜底②（地图塞满的极端位）不检查、照常兜底。
- 生成用 `random` 模块（与现有地形同路径）；单测用**注入 hmap + 不变式断言**，不赌 seed。

## 8. AI

- `_open_ahead` / `_nearest_opp` / 转向逻辑传 `cur_h`（蛇头所在格 h）：只避"上行 ≥2"与深渊，**不改战术智能**（不给 AI 高地意识、不主动抢山）。
- AI 出生同样走 h==0。
