## 0. 问题陈述（为什么做）

用户原话：「当前给危险地形标记红色是不是违背了美学」「红色……仿佛不是贪吃蛇世界里的东西」「根本原因是当前的地图本质还是个二维地图 只是加入了一点点突起和假的必死的所谓深渊坑」。

代码核实后的诊断：

1. **重力是单向规则不是物理**：死亡判定只有「上行 ≥2 即死、下行永远自由」（serve.py:1930-1932），从 3 格楼跳下零代价。
2. **「深渊」从未存在**：h=9 哨兵只在客户端渲染（index.html:2224/2255/2269/4266）、弹道飞越（serve.py:2255）和测试（test_game.py:3416/3482）里存在；`gen_heights`（serve.py:948-1045）从不生成 9。它是「假的必死的所谓深渊坑」——甚至没有假到玩家眼前。
3. **红色警戒栅栏语言错位**：批41 的橙红致死警戒（rebuildFatalEdge，index.html:2306+）是 3D 平台游戏的工地围挡语言，插在本质是 2D 棋盘+高度贴片的世界里，凭空多出一套与金框/青边无血缘的色系。

结论：修颜色是治标。用户拍板走**路线乙**——让高度成为物理。

## 1. 用户拍板的五个核心决策

| # | 决策点 | 拍板 |
|---|---|---|
| 1 | 3D 化档位 | **A. 网格步进 + 真垂直物理**（蛇仍一格一格走，高度成为物理；不做连续空间自由 3D） |
| 2 | 坠落后果 | **b. 断尾止损**：落差 2~3 断 N 节尾巴不死，≥4 才死（不引入 HP） |

| 4 | 坠落结算 | **a. 服务端瞬时结算 + 客户端坠落动画**（协议零新状态，不做多 tick 腾空） |
| 5 | 深渊形态 | **a. 真深坑**：一个特别深的洞，掉进去走通用坠落规则死，无特殊条款 |

## 2. 规则内核（服务端）

全场一套物理语言，无特例。设 `cur_h = hmap[移动前头格]`，`dst_h = hmap[目标格]`（稀疏表缺省 0）：

| 事件 | 条件 | 结果 |
|---|---|---|
| 爬坡 | `dst_h - cur_h == 1` | 可走，**tick × 1.5**（叠加顺序：speed → 水洼 → 爬坡 → slow，即在 tick_of 现有链上加一环） |
| 撞垂直崖 | `dst_h - cur_h >= 2` | 与撞墙同构：照死（cause='cliff' 已存在，serve.py:1948），walldeflect/shield 折返照旧；ghost 豁免照旧（serve.py:1932） |
| 平走/下浅坡 | 落差 ≤1 | 无事（含进水洼，水减速 30% 照旧 serve.py:1523） |
| **坠落断尾** | `cur_h - dst_h ∈ [2,3]` | **断 N = 落差-1 节尾**（2→1 节、3→2 节），复用 cut_one 语义（serve.py:1461-1466）：`MIN_LEN=2` 保底，只掉长度**不扣分**（与蒸发/融化断尾同语义） |
| **坠亡** | `cur_h - dst_h >= 4` | 死，**新死因 cause='fall'** |
| ghost | 坠落伤害/坠亡 | **不豁免**（重力对 ghost 生效：ghost 穿崖豁免后可站上高台，再从高台走下照吃坠落伤害） |

`death_stats.py` 加 'fall' 桶。**明确不变的**：tick 步进模型、稀疏表语义（0 缺省）、水洼减速、超导 slow。

### 2.1 坠亡结算位置（oracle B1）

服务端 step 管线中**淘汰结算循环在移动段之前**（serve.py:2041-2049 负责 alive=False/ev('die')/星尘/遥测 `_die_telemetry`），因此：

- **坠亡检测放 section 4 循环**（serve.py:1923-1948，与 cliff 检测同处）：用 `tent[id(p)]` 算 `cur_h - dst_h >= 4` → 进 `dead` 集合、`cause='fall'`，由 2041 循环统一收尾——**不写第二套死亡处理**。shield/折返重算后的新 `tent` 同样参与坠亡检测（折返候选已过滤致命坠落见 §5，此处兜底复检）。
- **坠落断尾（2~3 档）放 section 6**（头落新格后、吃果结算前、常规缩尾处）。

### 2.2 断尾与缩尾/吃果的叠加（oracle H1/H7）

- **坠落断尾取代本 tick 常规缩尾**：fall_cut 置标记，跳过 serve.py:2106 的 `cells.pop()`——落差 3 无论吃果与否都净掉 2 节（测试钉死「落差3+无果=掉2节」「落差3+吃果=掉2节」）。
- **吃果不取消坠落伤害**（与「吃果取消常规缩尾」语义相反）——明文+测试。
- 坠落断尾的 victim 若同 tick 被咬则本 tick 跳过移动（skip_move 既有不变量），无双重截断。
- 坠落断尾可将蛇降至 MIN_LEN=2，之后沿用「MIN_LEN 再被咬=整条淘汰」既有规则（serve.py:2008）——测试补「落差3→len2→下tick被咬→cause=bite 淘汰」级联。

### 2.3 其余明文（oracle H2/M3/L1/L3/L4）

- **爬坡减速方向基准**：tick_of 在方向队列应用之前执行（serve.py:1785 vs 1797-1801）——以 **tick_of 时刻 `p['dir']` 为准**，转向 tick 按旧方向可能误/漏算一格，接受此近似（只影响节奏不影响结算正确性）；测试覆盖转向 tick。
- **crush/对头 stance**：高度裁决一律取**移动前**头格高，坠落不改变本 tick crush 结果——成文+测试。
- **坠落不介入对头/clash 流程**（serve.py:1848-1855 同格僵持判定照旧）。
- **respawn 房间坠亡**：走既有 spawn_player（强制 h==0 出生格），无新语义。
- **幽灵姊妹用例**：ghost 穿崖上高台→走下吃坠落伤害（test_game.py:3387 现有 ghost 用例的姊妹篇）。

## 3. 深渊 = 真深坑（h 语义迁移）

- **哨兵 9 → -9**（负=向下的深度，与水 -1 / 草 -2 同族）：`gen_heights` 新增深渊 blob（2~4 格，walk_blob+take 基建，避开 ok() 一切约束含头±4）。**这是深渊首次真正生成**。**挂 `eff_water()` 旋钮**（预算 area/450 × eff_water；熔岩主题 water=0 → 天然无深渊，与无水无草同语义；保住 test_game.py:3297/3300 两条既有断言——三旋钮全 0 = 纯平地、熔岩无负值地形，列入 §7 迁移清单）。
- 坠入 = 落差 9 → 走通用坠亡（§2），无任何特殊拒绝条款。
- **弹道**（serve.py:2253-2255）：`hh != 9` 子句**直接删除**——hh=-9 时 `hh > pr['h']` 天然为假，-9 自动飞越（oracle M4：子句是死代码）。
- **reach_set**（serve.py:1336）与 **occupied**（serve.py:1066）：拦 -9（见 §5 转移规则）。
- **客户端 visH**（index.html:2221）：新增 `h === -9 ? -2.2` 分支——否则 -9 映射 0、坠入深渊动画没有视觉落点（oracle M2）；井壁底与坠落动画目标 Y 共用 -2.2。hKindOf 的 'ab' 判断改 `h === -9`；小地图特殊绘制（index.html:4264-4266）同步 -9。

## 4. 客户端渲染

### 4.1 坠落动画（协议零新状态）

现成基础：客户端蛇身逐节按 `visH` 插值（index.html:3898-3916），且客户端持有全量 hmap——坠落对**自己与远端蛇**同样生效。

改动：头（及身体逐节）走向低 ≥2 格的那一步，Y 插值从线性改为**重力加速曲线**（ease-in：`t²`），落地帧加：轻微落地顿挫（y 过冲 -0.03 回弹）、尘土粒子（复用 burst()，灰白色系）、落差 ≥4 时相机微震（复用 shake）。纯渲染层，服务端状态照常。

- **死亡呈现延迟**（oracle H6）：观测到坠落步（本地 hmap 可判落差 ≥2）时，该蛇的死亡呈现（die 事件的爆散/移除）**延迟到坠落动画结束**（约一个 step 间隔）再执行——否则 die 与 step 同批到达、尸体先被抹掉，坠落动画没机会播。协议不变，纯客户端呈现层。
- **动画中断规则**（oracle M5）：任何进行中的坠落动画被下一 step **硬替换**（从当前 y 直接进入新插值），不排队不叠加——防低 tick 蛇 ~150ms 间隔下回弹与新插值叠加抖动。

### 4.2 深渊井壁（替换死特性黑柱）

h=-9 的 'ab' 渲染从「地板下黑柱」（index.html:2269）改为**向下延伸的井**：四面内壁（深色、越深越暗的渐变或分段变暗盒体）+ 底部黑雾面片 + 口沿保留青边描线（沿用 hEdgeMat 青色 0x7fd8ff 的世界语言）。深度视觉封顶约 2.2 世界单位（≈6 格物理深，不必画满 3.15）。小地图特殊绘制（index.html:4264-4266）同步 -9。

### 4.3 批41 橙红警戒栅栏**退役**

删除 rebuildFatalEdge 全套（hFenceMat/hDeadEdgeMat/警示条/立面/轮廓线，index.html:2242-2360 区段及相关调用点 syncHeight 内、探针 __fatalDbg 改写）。理由：

1. 真物理下高差**本身可见可读**（H_UNIT=0.35 每格真实高差），围挡画蛇添足；
2. 用户最初的美学抱怨正是这套红色——路线乙把警戒交给物理因果，红色户口问题连根拔除；
3. 深渊井壁用青边世界语言承担「一眼读出致命」的职责。

## 5. 地形连通性与 AI

- **生成保证**：脊线山脉两侧 h=1 缓坡照旧（serve.py:992-1007，已有基础）；建筑 h2 入口坡从 60% 提为 100%，h3 也给入口坡；缺侧巨峭壁保留（30%）——它是「跳下去断尾」的博弈道具，不是错误。
- **可达性单一事实源 = reach_set**（oracle H4）：**不**在 gen_heights 尾部另跑独立 flood（两套规则必然漂移）。只改 reach_set（serve.py:1326-1367）的邻接转移规则化——从无权 BFS 改为：`dst_h - cur_h <= 1` 可进（爬坡）；`cur_h - dst_h <= 3` 可进（带伤断尾坠落）；`dst_h == -9` 或 `cur_h - dst_h >= 4` 不可进（致命）；`hh >= 2` 的无条件 block 删除（h≥2 顶经坡道可达）。**食物/星星/道具投放只落可达格**（place_food 走 reach_set 集成点）。孤峰=景观，绝不生成「看得见吃不到」。测试：「无坡 h3 顶不落食物 / 有坡 h3 顶落食物」。
- **`_solid` 扩展**（oracle H3）：cur_h 分支增加 `dst_h <= cur_h - 4 → True`（致命坠落视作实心）——否则 bot 贪心回落路径（`_bot_think` serve.py:1751-1753 经 `_solid` 避障）会沿贪心打分走下 ≥4 悬崖摔死。`_open_ahead`/`_nearest_opp` 经 `_solid` 自动继承。测试「悬崖顶食物在 cap 外时 bot 不自杀」。
- **bot 寻路**（`_bot_path_step` serve.py:1657-1711）带高度代价：现状 bot BFS **完全无视 hmap**（现存缺陷：会规划穿山路线撞死）。修复：上行 ≥2、坠落 ≥4、深坑 -9 = block（`_solid` 语义复用）；代价：爬坡 1 格记 2、坠落 2~3 记 4（宁绕不摔）、平走/下浅坡记 1——BFS 改**小顶堆 Dijkstra**，cap 提至 4×（加权后同 cap 有效半径缩水，oracle 建议），平局仍优先当前直行；测试补「cap 边界处绕崖路径能找到」回归。
- **`_deflect_dir` 高度过滤**（oracle H5）：折返候选（serve.py:2111-2128）增加 cur_h 参数，过滤上行 ≥2、致命坠落（下行 ≥4）、hh == -9——否则护盾/折返会把蛇弹进深渊（§2「护盾/折返语义不变」修正为「候选集纳入高度过滤」）。测试「盾牌撞崖折返不落 -9」。
